# Руководство по локальному SOCKS5-шлюзу `proxy2proxy`

## 1. Назначение и архитектура

`proxy2proxy` — лёгкое нативное приложение для macOS на Go и Objective-C (Cocoa) без сторонних зависимостей. Оно поднимает локальный SOCKS5-сервер без авторизации (по умолчанию на `127.0.0.1:1080`) для браузеров и утилит и направляет TCP-соединения на выбранный удалённый прокси-сервер (`http` или `socks5`, с необязательной авторизацией) строго через указанный сетевой интерфейс (например, `en0`, `en1`). Это позволяет обходить системный приоритет интерфейсов macOS и проблемы с авторизацией SOCKS5 в Chromium. Защита от DNS-утечек работает только когда браузер передаёт домены через SOCKS5 (включён удалённый DNS).

### Ключевые возможности

* **Внешний конфиг `config.json` без пересборки:** профили удалённых прокси, локальный порт и интерфейс по умолчанию задаются в JSON-файле рядом с `.app`-бандлом.
* **Два селектора в окне:** переключение на лету между активными сетевыми интерфейсами (`en0 Ethernet`, `en1 Wi-Fi` и др.) и списком удалённых прокси-серверов без перезапуска сервиса.
* **Поддержка протоколов `http` и `socks5` (или `socks`):** HTTP `CONNECT` и SOCKS5 (RFC 1928 / RFC 1929) с базовой / логин-пароль авторизацией. Локальный SOCKS5 принимает только TCP `CONNECT`; UDP ASSOCIATE и BIND не поддерживаются.
* **Жёсткая привязка к интерфейсу (`IP_BOUND_IF`):** исходящие TCP-сокеты привязываются к индексу выбранного интерфейса на уровне ядра Darwin/macOS.
* **Живой мониторинг и индикатор в Dock:**
  * Отображение в реальном времени количества активных сессий и текущей скорости скачивания/отдачи (`↓ ... ↑ ...`).
  * Гибридная проверка доступности маршрута: успешные реальные соединения подтверждают статус пассивно, а активная проверка по контрольным целям запускается при старте, при смене маршрута, после ошибок и когда давно не было успешных соединений.
  * Кастомная скруглённая иконка приложения (`AppIcon.icns`) с динамическим индикатором статуса в правом верхнем углу Dock: **зелёный кружок** при активной связи, **красный** при потере соединения или ошибке сети.
* **Перехват сбоев и логирование:** перехват паник Go и исключений Cocoa (`NSException`) с выводом системного диалога (`NSAlert` / `osascript`) и записью журнала в `~/Library/Logs/proxy2proxy.log`.
* **Два режима сборки:** быстрая локальная сборка под текущую архитектуру (`arm64` на Apple Silicon) или универсальный бандл (`arm64` + `x86_64`) для переноса на любые Mac.

```
[Браузер: 127.0.0.1:1080 (SOCKS5 без пароля)]
                      │
                      ▼
  [proxy2proxy.app (Cocoa UI + Go Core)]
                      │  (привязка сокета IP_BOUND_IF к выбранному enX)
                      ▼
[Интерфейс enX] ──► [Удалённый прокси: http / socks5 с паролем] ──► [Интернет]
```

## 3. Настройка `config.json`

Скопируйте `config.example.json` в `config.json` и отредактируйте его под свои прокси. Рабочий `config.json` указан в `.gitignore`, поэтому пароли из него не попадут в репозиторий. При запуске приложение ищет `config.json` в той же папке, где лежит `proxy2proxy.app` (`~/Applications/proxy2proxy/config.json`). Пересобирать приложение при изменении серверов **не требуется** — достаточно отредактировать `config.json` и перезапустить программу.

Пример `config.json`:

```json
{
  "listen": "127.0.0.1:1080",
  "iface": "en0",
  "proxies": [
    {
      "name": "EU SOCKS5",
      "type": "socks5",
      "addr": "203.0.113.10:1080",
      "user": "my_login",
      "pass": "my_password"
    },
    {
      "name": "US HTTP",
      "type": "http",
      "addr": "198.51.100.25:8080",
      "user": "user2",
      "pass": "pass2"
    }
  ]
}
```

### Поля конфигурации

* `listen` — локальный адрес и порт SOCKS5-сервера (по умолчанию `"127.0.0.1:1080"`).
* `iface` — BSD-имя сетевого интерфейса по умолчанию при старте (например, `"en0"`, `"en1"`).
* `proxies` — список профилей удалённых прокси:
  * `name` — отображаемое имя в выпадающем списке окна (если не задано, формируется автоматически).
  * `type` — тип прокси: `"socks5"` (или `"socks"`) либо `"http"`.
  * `addr` — адрес удалённого прокси в формате `"host:port"`.
  * `user` / `pass` — логин и пароль (оставьте `""`, если авторизация не требуется).
* `status_check_targets` — необязательный список контрольных целей активной проверки в формате `"host:port"`. Если поле отсутствует или все записи некорректны, используются `example.com:443`, `example.org:443` и `one.one.one.one:443`.


## 4. Варианты сборки и обновление иконки

Убедитесь, что установлены Xcode Command Line Tools (`xcode-select --install`) и Go версии из `go.mod`. Сборка рассчитана на macOS 12 и новее. В проекте доступны два скрипта сборки — оба автоматически подключают `AppIcon.icns`, копируют локальный `config.json` или шаблон `config.example.json`, если целевого конфига ещё нет, и подписывают бандл в `~/Applications/proxy2proxy/proxy2proxy.app`.

### Вариант А: Быстрая сборка под текущий Mac (Apple Silicon / `arm64`)
Подходит для повседневной разработки и локального использования на Apple Silicon — компилирует один `arm64` бинарный файл. Приложение после сборки нужно запустить отдельно:

```bash
./build_app.sh
```

### Вариант Б: Универсальная сборка (`arm64` + `amd64`)
Собирает два бинарных файла (для Apple Silicon и Intel Mac) и склеивает их в Universal Binary с помощью `lipo`. Используйте этот вариант, если планируете переносить `.app` на другие компьютеры Mac:

```bash
./build_universal.sh
```

### Обновление кэша иконки в Dock
Если после замены `AppIcon.icns` macOS продолжает показывать старую иконку в Dock, сбросьте кэш:

```bash
touch ~/Applications/proxy2proxy/proxy2proxy.app
killall Dock Finder
```

## 5. Автозапуск при входе в систему (Login Items)

1. Откройте **Системные настройки** → **Основные** → **Объекты входа** (Login Items).
2. В разделе **Открывать при входе** нажмите **«+»**.
3. Нажмите `Cmd + Shift + G`, перейдите в `~/Applications/proxy2proxy`, выберите **`proxy2proxy.app`** и нажмите **Открыть**.

## 6. Как работает гибридная проверка статуса

Индикатор в Dock и статус в окне отвечают на вопрос: работает ли текущий маршрут «выбранный интерфейс → выбранный upstream-прокси → интернет». Проверка гибридная, чтобы не зависеть от одного контрольного сайта и не делать лишних синтетических запросов, когда реальный трафик уже доказал, что маршрут жив.

1. **Пассивная часть.** Когда реальное клиентское соединение успешно проходит через upstream (`CONNECT` до сайта назначения удался), приложение запоминает время успеха для текущего маршрута. Если это первый свежий успех после красного статуса или смены маршрута, иконка сразу становится зелёной.
2. **Активная часть.** При старте, при смене интерфейса или прокси, после ошибок и периодически, когда свежих успешных соединений давно не было, приложение делает контрольные CONNECT через upstream к целям из `status_check_targets`. По умолчанию это `example.com:443`, `example.org:443` и `one.one.one.one:443`; успех любой цели означает зелёный статус, а задержка в окне измеряется для успешной цели.
3. **Свежесть и пинг.** Реальный успех подавляет синтетическую проверку только на 30 секунд: если реального трафика нет, активная проверка обновляет задержку каждые 30 секунд. Как доказательство живого маршрута реальный успех учитывается 5 минут, чтобы медленная активная проверка не перекрасила статус в красный, пока реальные соединения уже работают. При неудаче активной проверки статус становится красным, а повторные попытки идут каждые 30 секунд.
4. **Ошибки реальных соединений.** Одна ошибка до конкретного сайта не обязана означать смерть прокси, поэтому она не красит статус сразу, а запускает активную перепроверку маршрута. Если интерфейс не активен или не получил нормальный IP, маршрут считается недоступным и трафик не уходит в обход выбранного интерфейса.

## 7. Настройка браузера

В настройках прокси браузера или расширения (ZeroOmega, Proxy SwitchyOmega, Firefox) укажите:

* **Протокол:** `SOCKS5`
* **Сервер:** `127.0.0.1`
* **Порт:** `1080`
* **Авторизация:** пусто (авторизацию на удалённом сервере выполняет `proxy2proxy`).
* **DNS:** включите **«Удалённый DNS»** (*Proxy DNS when using SOCKS v5*), чтобы DNS-запросы не утекали мимо туннеля.

Локальный SOCKS5 не требует пароля. Оставляйте `listen` равным `127.0.0.1:1080`, если прокси нужен только этому Mac; значение `0.0.0.0:1080` откроет его локальной сети. Пароли в `config.json` хранятся открытым текстом, поэтому для рабочего файла разумно выполнить `chmod 600 ~/Applications/proxy2proxy/config.json`. Пароли к upstream HTTP/SOCKS5 передаются самому прокси без TLS, если upstream не поддерживает защищённый транспорт.

## 8. Полезные команды и диагностика

* **Запустить приложение:**
  ```bash
  open ~/Applications/proxy2proxy/proxy2proxy.app
  ```

* **Проверить внешний IP через локальный шлюз:**
  ```bash
  curl --socks5-hostname 127.0.0.1:1080 https://ifconfig.me
  ```

* **Проверить, что порт `1080` прослушивается:**
  ```bash
  lsof -i :1080
  ```

* **Посмотреть лог ошибок и событий:**
  ```bash
  tail -f ~/Library/Logs/proxy2proxy.log
  ```

* **Остановить приложение из терминала** (или закройте его окно крестиком / `Cmd + Q`):
  ```bash
  killall proxy2proxy
  ```
